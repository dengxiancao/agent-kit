从零开始：在手机上装一个能自己动手的 AI 助手

零基础版 · 2026.11.19 · 全程约 40 分钟

这份文档假设你什么都不会：没用过 Linux，不知道 Python 是什么，看到 pkg install 这种命令不知道在干什么。

所以它很啰嗦。每一步都写清楚四件事：

  • 要你做什么（照抄那一行）
  • 这行命令到底在干什么（用大白话）
  • 成功长什么样（你应该看到什么字）
  • 没成功怎么办（最常见的三种错，各自怎么修）

已经会 Linux 的人不用看这份，去看 MANUAL.html，那是速查版。

全程只用手机，不需要电脑。有电脑的话第 8 章讲怎么在电脑上装第二份。

读完你能得到什么

一个在手机里跑的东西，你打字跟它说话，它自己去执行命令、看文件、点屏幕、识别图片，然后把结果告诉你。

它住在你自己的手机里，不经过任何第三方服务器，除了调用 AI 模型那一下。

第 0 章 先搞清楚这是什么东西

0.1 一句话

它把你的话翻译成一串命令，在你手机上执行，再把结果说给你听。

你说「看看 download 目录里有什么」，它就去执行 ls ~/download，然后把输出整理成人话回给你。

和普通 AI 聊天框的区别只有一个：它真的能动手。普通 AI 只能告诉你「你可以执行 ls 命令」，这个会直接执行。

0.2 它能干什么

下面这些是真实能跑通的，不是演示：

你说它做
「看看我手机还剩多少空间」执行 df -h，告诉你哪个分区快满了
「download 里有个 apk，帮我看看要哪些权限」解析 APK，列出危险权限和用途
「打开微信，给张三发个消息说我在路上」通过 ADB 点开应用、找到联系人、输入文字、点发送
「这张截图里写了什么」截图 + OCR，把文字和坐标都给你
「把这个 PDF 每页的文字提出来，存成 txt」逐页 OCR，写文件

它还能组合：你说「去设置里把深色模式打开」，它会先看当前屏幕有什么，再点「显示」，再点「深色」，每步确认一次。

0.3 它不能干什么

说清楚边界，省得你怀疑自己装错了：

做不到原因

保证每次都点对它靠识别屏幕文字定位，界面改版就可能点偏
离线使用每句话都要调一次 AI 模型，需要联网

装成 App 点图标启动它是命令行程序，靠浏览器界面操作

项目要求说明

第 1 章 装 Termux

1.1 它是什么

Termux 是一个安卓 App，但打开之后不是图形界面，而是一个终端——黑底白字，等你在光标处打命令。

它的价值在于：它自带一整套 Linux 工具（ls、cat、curl、python……），装完相当于在手机里塞了一台小电脑，而且不需要 root。

1.2 从哪里下载（这里容易装错，看清楚）

不要从华为应用市场、小米应用商店、应用宝下载。 那些版本大多停留在 2020 年，目标 API 版本太低，安卓 12 以上直接装不上，或者装上了 pkg 命令一跑就报错。

只用下面两个来源之一：

来源地址说明
F-Droid（推荐）f-droid.org/packages/com.termux开源应用商店，页面往下拉有「下载 APK」
GitHub Releasesgithub.com/termux/termux-app/releases找文件名里带 universal 的那个（形如 termux-app_v0.118.x-universal.apk），它适配所有机型

下载完点开 APK，系统会提示「未知来源应用」，允许一次即可。装完桌面会出现一个黑底 >_ 图标的 App。

如果你之前装过应用商店版本，先卸载再装。两个版本签名不同，覆盖安装会失败，而且旧版本残留的配置会让新版本行为诡异。

1.3 第一次打开

点图标进去，你会看到类似这样的一屏：

最后那个 $ 就是「等你输入」的意思。光标在那儿闪。

这时候不要急着打命令，先花两分钟认识键盘。

1.4 认识这个界面

手机上没有实体键盘，Termux 的输入方式和普通 App 不一样：

你想做怎么做
输入命令直接点屏幕下方弹出的输入法，和平常打字一样
粘贴长按屏幕空白处 → 弹出菜单选「Paste」。不要去点输入法上的粘贴，经常无效
复制屏幕上的字长按要复制的文字，拖动选择范围 → 点「Copy」
打出 Ctrl 组合键音量减 + 字母键。比如 Ctrl+C 就是音量减 + C
上下翻看历史输出手指在屏幕上上下滑
调出命令历史的上一行音量加 + 方向键（有些机型没反应，直接用 ↑ 更稳）
切换成英文输入法命令必须用英文符号，中文输入法会把 " 变成 ”，导致报错
这一条踩过的人最多：命令里的引号、括号、斜杠必须是英文半角。中文输入法下打出来的 “” 和 （） 会让命令直接失败，报错信息还很难懂。输入命令前先把输入法切到英文。

放大字号（可选，眼睛累的话）：双指在屏幕上捏合放大，和看图片一样。这只影响显示，不影响命令。

1.5 必做的三条设置

按顺序执行，一条一条来，等上一条跑完再打下一条。

第一条：换成国内镜像源

termux-change-repo

这条命令在干什么：打开一个文字界面的选择菜单，把「去哪里下载软件」从国外服务器改成国内镜像，下载速度能从 10 KB/s 变成几 MB/s。

执行后会看到这样的选择界面：

[*] Mirror groups
[ ] Mirror

< OK >   < Cancel >

操作方式反直觉，注意看：

  1. 用方向键（屏幕键盘上的上下箭头）把光标移到 Mirror groups
  2. 按回车（输入法上的回车键，不是屏幕上的换行）
  3. 进到下一屏，列出 Grimler、Tsinghua、USTC 等，选 Tsinghua（清华）或 USTC（中科大）
  4. 再按回车确认
  5. 出现 < OK > 时按回车退出

成功的话不会打印什么，直接回到 $ 提示符。

这步也可以跳过。跳过的话后面装软件会很慢，但不会失败。网速本来就快（比如连了 WiFi 且能直连国外）就不用改。

第二条：更新软件列表

pkg update

这条命令在干什么：去服务器拉一份「现在有哪些软件、各自什么版本」的清单。它不装任何东西，只是刷新目录。

跑起来会刷很多行，中间可能停下来问你：

Do you want to continue? [Y/n]

打 y 然后回车。

成功的样子是最后回到 $，中间没有大片红色 E: 开头的错误。

失败怎么办：

报错原因怎么修
Unable to locate package源没配好重跑 termux-change-repo，选清华
Some index files failed to download网络断了换个网（WiFi 换流量）重跑
E: Repository ... is not signed源配置坏了执行 rm -rf /data/data/com.termux/files/usr/var/lib/apt/lists/* 再 pkg update
卡在 Reading package lists... 很久正常，在解压等 1-2 分钟

第三条：防止后台被杀

termux-wake-lock

这条命令在干什么：告诉安卓系统「别把我这个 App 睡死，我还在干活」。不执行的话，你一切换到别的 App，Termux 就被系统冻结，正在跑的任务直接中断。

执行成功没有任何输出，回到 $。

还要去系统设置里给它开绿灯（这步不能省，小米/华为/OPPO 尤其严）：

品牌路径
小米 / Redmi设置 → 应用设置 → 应用管理 → Termux → 省电策略选「无限制」；同页 → 自启动打开
华为 / 荣耀设置 → 应用 → 应用启动管理 → Termux → 关掉「自动管理」，手动勾选三项允许
OPPO / 一加设置 → 电池 → 应用耗电管理 → Termux → 允许「后台运行」
vivo设置 → 电池 → 后台耗电管理 → Termux → 允许后台高耗电
三星设置 → 电池 → 后台使用限制 → 从「睡眠应用」里移除 Termux
termux-wake-lock 每次重启手机都要重新执行一次。它不是永久设置，是一个临时锁。嫌麻烦可以把它写进启动脚本，但新手先手动执行。

1.6 检查点

到这里，Termux 应该满足：

  • 输入 pkg update 能正常跑完，不报红
  • 输入 termux-wake-lock 没反应（没反应就是对的）
  • 切到微信再切回来，Termux 还在原来的位置，没有重新加载

三条都满足，进第 2 章。

第 2 章 装 Python 环境

这一章是重点。Python 装不好，后面全部白搭。

2.1 Python 是什么，为什么必须装

大白话：rev.py、webchat.py 这些文件不是能直接双击运行的程序，它们是一堆给 Python 看的指令。就像一份菜谱，得有厨师才能变成菜。

Python 就是那个厨师。没装它，你输入 python3 webchat.py 只会得到「command not found」。

它有两部分：

部件作用怎么验证
解释器 python3读 .py 文件并执行python3 --version
包管理器 pip给 Python 装第三方库pip --version

我们这个项目只用标准库，理论上不需要 pip 装任何东西。但 OCR 那一章要装 pillow（处理图片），所以 pip 也得能用。

2.2 装解释器和 pip

pkg install -y python

这条命令在干什么：从镜像源下载 Python 3 的解释器，顺带把 pip 一起装上（Termux 的 python 包自带 pip）。-y 表示「所有问我要不要确认的地方，一律回答 yes」，省得你一路打 y。

会看到类似这样的过程：

Testing the available space...
Building dependency tree...
The following NEW packages will be installed:
  python
...
Unpacking python (3.12.x) ...
Setting up python (3.12.x) ...

成功的样子：最后回到 $，没有 E: 开头的红字。

失败怎么办：

报错原因怎么修
E: Unable to locate package python软件列表没更新先 pkg update，再重试
E: Sub-process ... returned an error code (1)上次没装干净pkg install -f python 修复依赖
No space left on device存储满了df -h 看哪个分区满，清点空间再来
卡在 Unpacking 一动不动下载中断Ctrl+C（音量减+C）中断，重跑同一条命令，它会接着下

2.3 验证

分两条命令，逐条执行：

python3 --version

应该看到：

Python 3.12.x

版本号 3.8 以上就行，Termux 现在默认给 3.12。数字不一样没关系，只要不低于 3.8。

接着：

pip --version

应该看到类似：

pip 24.x from /data/data/com.termux/files/usr/lib/python3.12/site-packages/pip (python 3.12)

只要出现 pip 和版本号就算成功，路径不用管。

如果 python3 有反应但 pip 报 command not found，单独装一次：pkg install -y python-pip。

2.4 装本项目要用的额外依赖

分三组，按需装。只聊天不控屏、不 OCR 的话，这步可以全部跳过，程序本身零依赖就能跑。

A 组：控屏（必装，如果要让它点屏幕）

pkg install -y android-tools

干什么：装 adb，就是让程序能模拟点击、滑动、截屏的那个工具。约 10 MB。

验证：

adb version

应该看到 Android Debug Bridge version 1.0.41 或更高。

如果版本低于 1.0.41，配对时会报 unknown command，必须 pkg upgrade android-tools。Termux 镜像里的版本一般已经是新的。

B 组：OCR（要读图片/PDF 才装）

pkg install -y tesseract poppler python-pillow

这三个分别是什么：

包作用大小
tesseract识别引擎本体，把图片里的字形变成文字约 30 MB
poppler提供 pdftoppm，把 PDF 每一页转成图片再识别约 15 MB
python-pillowPython 的图片处理库，ocr.py 用它做缩放和裁剪约 8 MB
不要用 pip install pillow。 那会现场编译 C 代码，手机上大概率失败，或者卡 10 分钟。Termux 官方已经把编译好的包命名为 python-pillow，用 pkg install 一步到位。

C 组：其他可选

命令什么时候需要
pkg install -y radare2要用 rev.py r2 反汇编
pkg install -y git想用 git clone 拉代码，而不是 curl 下文件
pkg install -y procps想用 pkill 结束进程（Termux 默认没有）

2.5 不要做的事

别做为什么
pkg upgrade全量升级几百 MB，耗时半小时以上，中途断网会把系统搞坏。只装缺的包就够了
pip install --upgrade pipTermux 的 pip 和系统包管理器有绑定，升级后可能装不上任何东西
从应用商店装「Python 编辑器」类 App那些是另一个 App，和 Termux 里的 Python 半毛钱关系没有
apt installTermux 用的就是 pkg，apt 能用但路径和参数有差异，新手别碰

2.6 检查点

逐条执行，全部通过再往下：

python3 --version
pip --version
adb version

前两条必须有输出。第三条如果第 2.4 节 A 组装了才有，没装会报 command not found，正常。

再跑一个真正的 Python：

python3 -c "print('环境正常')"

应该原样输出：

环境正常

这行不通，说明解释器有问题（不是路径问题就是装坏了），先解决它，别往第 3 章走。

第 3 章 把程序下载到手机

3.1 先搞清楚「装在哪」

Termux 里所有的操作都在一个「当前目录」里发生。你可以用这条命令看看自己在哪：

pwd

会输出：

/data/data/com.termux/files/home

这就是 Termux 的家目录，等价于 ~。你每次新开 Termux 都站在这里。

我们要建一个专门放程序的文件夹：

mkdir -p ~/work
cd ~/work

这两条在干什么：

  • mkdir -p ~/work：创建 work 文件夹。-p 的意思是「如果已经存在就别报错」
  • cd ~/work：把当前目录切到 work 里。cd 是 change directory

再 pwd 一次，应该变成：

/data/data/com.termux/files/home/work

后面的下载、启动，全部要在这个目录里做。忘了在哪就先 pwd。

目录名叫 work 只是习惯，叫 abc 也行。但整份手册和你以后看到的教程都用 ~/work，跟着用省事。

3.2 方式 A：一句命令全下（推荐）

这个仓库带了一个更新脚本 update.sh，它知道所有文件在哪、下完会校验、失败会自己换镜像。

第一步，把脚本本身下下来：

curl -fL -o update.sh.part "https://ghfast.top/https://raw.githubusercontent.com/dengxiancao/android-agent-kit/main/update.sh" && mv update.sh.part update.sh

这行在干什么：curl 是下载工具。ghfast.top/ 是国内镜像前缀，原地址整段接在它后面。-f 表示「服务器返回错误就直接失败」，-L 表示「遇到跳转跟着走」。

-o update.sh.part 是先存成临时名字，&& 意思是「前一条成功了才执行后面」，mv 再改名。

为什么不直接 -o update.sh：万一网络断了，curl 会留下一个 0 字节的空文件，把你的旧脚本覆盖成废文件。这个坑踩一次就够，所以所有下载都先写 .part。

第二步，跑它：

sh update.sh

这条在干什么：用 sh 解释器执行 update.sh，它会去仓库把 rev.py、webchat.py、adui.py、ocr.py、手册、static/ 三件套全部拉下来。

成功会看到：

镜像  ghfast.top（失败自动换下一个）

  ✓ rev.py        新增 28616

看到「新增」就是成功。 数字是你机器上实际下到的字节数，和上面不完全一致没关系（版本更新会变大小），但不应该是 0。

以后换新版，只要在这个目录里执行一句：

sh update.sh

它自己会比对内容，没变的不写盘，变了的才替换，还会把旧的存成 .bak。

3.3 方式 B：手动逐个下载（脚本抽风时用）

update.sh 也下不下来的时候（镜像全挂），用这段。整段复制，一次粘贴：

BASE="https://ghfast.top/https://raw.githubusercontent.com/dengxiancao/android-agent-kit/main"

for f in rev.py webchat.py adui.py ocr.py update.sh; do
  curl -fsSL -o "$f.part" "$BASE/$f" && [ -s "$f.part" ] && mv "$f.part" "$f" && echo "ok $f"
done

mkdir -p static

for f in app.html app.css app.js; do
  curl -fsSL -o "static/$f.part" "$BASE/static/$f" && [ -s "static/$f.part" ] && mv "static/$f.part" "static/$f" && echo "ok static/$f"
done

这段在干什么：BASE 是把镜像前缀存成一个变量，省得写八遍。for f in ... 是一个循环，把括号里每个名字依次当成 f 执行中间那段。[ -s "$f.part" ] 是判断「这个文件存在且不是空的」。

逐行输出 8 个 ok 就成功了。

单个文件下载失败时，最稳的办法是手动重跑对应那一行。不要用 wget -O 目标文件，它在失败时会先把目标文件清空，把好的版本毁掉。

第 4 章 申请一个 API key

4.1 这个东西是什么

程序本身不会思考，它每说一句话都要把上下文发给远端的 AI 模型，模型算完把结果发回来。

API key 就是这次调用的身份证 + 付款凭证：模型服务商靠它认出「这是谁在调用」，然后从那个账户扣钱。

所以：

  • 没有 key，程序启动会直接退出，提示「缺少 DEEPSEEK_KEY」
  • key 泄露，别人可以用你的 key 花你的钱
  • key 一般只显示一次，页面关掉就看不到了

4.2 注册和充值

打开 https://platform.deepseek.com ，用手机号注册并登录。

然后先充值再创建 key，顺序反了会在第一次对话时收到余额不足的报错：

  1. 左侧菜单找「充值」或「账户余额」
  2. 充 10 元试水。按现在的价格，正常强度聊天一个月用不完
  3. 确认余额显示 10 元
计费方式是「按 token 用量扣」。一句话大约消耗几百到几千 token，具体价格随官方调整，看充值页上的实时说明。10 元差不多够你折腾一两个月。

4.3 创建 key

  1. 左侧菜单进「API keys」
  2. 点「创建 API key」，名字随便填（比如 phone）
  3. 立刻复制弹出来的那串字符，形如 sk- 开头、后面三十多位
  4. 存到一个临时地方（记事本、微信文件传输助手都行）

页面关掉之后就再也看不到完整 key 了，只能删了重建。先复制，再关页面。

4.4 把 key 存到手机里（一次配置，永久生效）

不要把 key 直接写在命令里。那种写法（DEEPSEEK_KEY=sk-xxx python3 webchat.py）每次重启手机就失效，而且会留在命令历史里被人翻到。

正确做法是写进配置文件。三条命令，逐条执行：

mkdir -p ~/.config/webchat
echo 'DEEPSEEK_KEY=sk-把这里换成你自己的key' > ~/.config/webchat/env
chmod 600 ~/.config/webchat/env

这三条在干什么：

  • 第一条：建一个隐藏配置目录（~/.config/webchat）
  • 第二条：把 DEEPSEEK_KEY=... 这一行写进 env 文件。把 sk-把这里换成你自己的key 整段替换成你复制的 key，单引号要保留
  • 第三条：把文件权限改成「只有你自己能读」。安卓上多用户或装了文件管理器的情况下，别的 App 读不到

验证写对了没有：

cat ~/.config/webchat/env

应该原样显示你写的那一行。key 不要发截图到群里，这一步自己看一眼就行。

4.5 这个文件还能写什么

env 文件里可以写多行，一行一个设置。常用的四个：

键默认值什么时候要改
DEEPSEEK_KEY无必填
AGENT_WORK~/work程序放在 ~/work-kit 时改成那
HOST127.0.0.1想让电脑/平板访问手机上的服务，改成 0.0.0.0
PORT8765端口被占用时换一个，比如 8800
AGENT_MAX_TURNS100单条消息最多执行几步，一般不用动

多行的写法就是多写几行：

DEEPSEEK_KEY=sk-xxxxxx
AGENT_WORK=/data/data/com.termux/files/home/work
HOST=0.0.0.0
这个文件里是明文 key。三件事别做：不要放进 git 仓库、不要截图发人、不要传到网盘。换手机迁移时也不要整个目录打包发给别人。

4.6 检查点

ls -l ~/.config/webchat/env

看到权限是 -rw-------（就是刚才 chmod 600 的结果），属主是你自己，就对了。

再看一眼内容长度合理（不会只有几个字符）：

wc -c ~/.config/webchat/env

sk- 开头的 key 大概 35 个字符，加上 DEEPSEEK_KEY= 一共 48 左右。差太多就是复制漏了。

第 6 章 让它能操作你的手机屏幕

这一章是全套里最容易卡住的地方。慢一点，一步一验。

6.1 原理：它凭什么能点你的屏幕

安卓系统里有个官方调试通道叫 ADB（Android Debug Bridge）。本来是给开发者用电脑连手机调试的，因为它能做的事和你的手指一样：点击、滑动、输入文字、截屏、读界面结构。

正常情况下 ADB 要通过 USB 线连电脑。安卓 11 之后加了无线调试，同一台手机上的两个 App 也能通过它通信——这就是 Termux 里的 adb 能操作本机屏幕的原因。

所以整个链路是：

webchat.py  →  adui.py  →  adb  →  安卓系统  →  你的屏幕

6.2 打开开发者选项

这个菜单默认是隐藏的，要用「连点版本号」的方式解锁。

vivo / iQOO设置 → 系统管理 → 关于手机 → 连续点「软件版本号」7 次

6.4 配对（只需一次）

点页面里的 「使用配对码配对设备」，会弹出一个框：

使用配对码配对设备

Wi-Fi 配对码
570100

Wi-Fi 配对
IP 地址和端口
192.168.1.102:42361

注意这里也有一行 IP:端口，这个端口（42361）和主页面的（39549）不是同一个。

90% 的失败都是因为拿错了端口。 记法：

你看到的用途用在哪
主页面上的 IP:端口连接adb connect
弹窗里的 IP:端口配对adb pair

关键：这个弹窗只活 2 分钟

锁屏、切到别的应用、把弹窗关掉，它立刻失效。所以不要抄在纸上再慢慢打，用分屏：

  1. 打开最近任务（多任务键或上滑悬停）
  2. 长按 Termux 图标 → 选「分屏」或「分屏显示」
  3. 上半屏选「设置」，让设置页面和 Termux 同时可见
  4. 在设置里点「使用配对码配对设备」拿到弹窗
  5. 在下面一半的 Termux 里直接敲命令

敲这条

把 42361 换成你弹窗里的端口，570100 换成你的 6 位码：

python3 adui.py pair 127.0.0.1:42361 570100

这条在干什么：让本机的 adb 用这个一次性端口和系统的无线调试服务握手，交换密钥。成功后密钥存在手机里，以后不用再配对。

成功会看到：

Successfully paired to 127.0.0.1:42361 [guid=adb-xxxxx]

然后它会自动开始扫端口（下一节的内容），等它扫完就行。

7.1 什么时候需要

7.3 装中文语言包

引擎本身只会认英文，中文要单独下模型文件。

先看现在有哪些语言：

如果输出里只有 eng 和 osd，需要补中文：

这两条在干什么：把简体中文和英文的识别模型下载到 ~/.tessdata，ocr.py 启动时会优先读这个目录。

补完再验一次：

tesseract --list-langs

现在应该能看到 chi_sim。

tessdata_fast 是速度优先的版本，手机上用这个。如果发现某些字总认错，可以换 tessdata_best（准确率高但慢 3-5 倍），把地址里的 tessdata_fast 改成 tessdata_best 重下一次即可。

7.6 认不准怎么调

OCR 不是万能的，尤其手机上字小、背景花。按这个顺序试：

问题加这个参数说明
整张图字太小--scale 2先放大两倍再认。默认按宽度自动判断

8.6 想让别的设备访问

默认只监听 127.0.0.1，也就是只有本机能连。要让手机、平板、宿主机访问，得改成 0.0.0.0：

python3 webchat.py --host 0.0.0.0

或者写进配置文件，省得每次敲：

echo 'HOST=0.0.0.0' >> ~/.config/webchat/env

改完之后用这台机器的局域网 IP 访问，不是 127.0.0.1：

ip addr | grep "inet 192"

假设输出 192.168.1.50，那就在浏览器打 http://192.168.1.50:8765。

虚拟机里还要多做一步：宿主机的浏览器访问虚拟机的端口，需要端口映射（NAT 转发）或把虚拟机网络设成桥接模式。

方式怎么做
桥接虚拟机设置 → 网络 → 桥接网卡。虚拟机会拿到和宿主机同网段的 IP，直接用那个 IP 访问
NAT + 端口转发虚拟机设置 → 网络 → 端口转发 → 添加：主机端口 8765，子系统端口 8765
--host 0.0.0.0 等于把这台机器上的命令执行权开给整个局域网，而这个界面没有密码。同一 WiFi 下的任何人打开浏览器就能让它执行任意命令、看你的会话记录。只在完全信任的网络里这么用，用完改回默认。

sh ~/start.sh

附录 C 安全边界

这套东西的权限很大，说清楚它到底能做什么：

能力意味着
执行任意 shell 命令它能删除你的文件、改系统设置、装软件。它不会主动这么干，但你要知道有这个能力
ADB 全权限能点任何界面、读任何屏幕内容、安装卸载应用
读工作目录所有文件包括你放在 ~/work 里的 apk、截图、文档
会话库存明文sessions.db 是你在这台机器上干过的所有事的完整记录
网页界面无密码--host 0.0.0.0 时，同网段任何人打开浏览器就能指挥它

几条硬建议：

  1. HOST 保持默认的 127.0.0.1，除非你清楚局域网里都有谁
  2. key 不要贴在聊天里、不要提交到 git，泄露后立刻去后台删掉重建
  3. sessions.db 别乱传，里面有你的目录结构、文件名、命令历史
  4. 重要操作前让它先 look 确认，别一句「把照片全删了」扔过去
